# ADR 0007 — V1 幼体不默认迁移 V0 数据

- **Status**: accepted（2026-09-13，STEP 12）
- **约束来源**: 材料 1 §7/§9（幼体 = "完整但未成熟"；最小完整体："先创造最小完整体，不先堆功能 / 知识 / 人格 / 工具"）；R-10（V0 数据迁移 UNKNOWN，用户决策）；ADR 0001（决定中"V0 数据迁移不预设"的落点）；规则 11（UNKNOWN 不得猜测）/ 规则 12（不默认 KEEP）；H-4（`memory/models.py` 向后兼容推断行硬编码 `provenance=="hermes_desktop"`）

## Context

V0 存在既有数据：`soul.json`（Identity 载体）、SQLite 记忆（三维语义层记忆项）、capabilities/ 四目录。V1 是否迁移这些数据**无材料依据**（UNKNOWN，STEP 08 新增，联动 R-10）。V0 数据的权威 = Implementation（权威顺序最低级）；V1 幼体的起点由 Original Intent 定义（材料 1 §9：最小完整体——不先堆知识 / 人格 / 工具），不由 V0 存量定义。

## Decision

1. **V1 幼体不默认迁移 V0 数据**（`soul.json` / SQLite 记忆 / capabilities 四目录）：V1 从新的最小完整体开始——旧数据不是幼体"完整"的前提（材料 1 §7：完整 = 基本结构已完整，不是内容已堆满）。
2. **迁移是用户决策，不是默认行为**：若用户决定迁移部分 / 全部，那是一个独立迁移任务——迁移工具是一次性工具行为（Ontology 映射 + 数据变换），不进入 Core、不成 Runtime 的一部分；届时 V0 的向后兼容推断逻辑（H-4：`kind=="experience" and provenance=="hermes_desktop"` → canonical）归**迁移工具**，不留在 Ontology 推断层（R-10 分支 2）。
3. **UNKNOWN 保留**：本 ADR 决定的是**默认值（不迁移）**与**决策权（用户）**，不是迁移的最终状态——"V1 是否迁移 V0 数据"在用户决定前保持 UNKNOWN（规则 11：默认值 ≠ 对最终状态的推断）。
4. **V0 数据不构成 V1 依据**：其内容（6 条 doctrine 文本 / 8 根 faculty / 语义层记忆项等）进入 V1 只经**设计层逐条追认或重写**（Q1 / Q3 为先例：6 条 = 当前成文子集已追认、8 根 = 初始集已追认——这些是设计层行为，不是数据迁移，联动 ADR 0005 决定 5）。

## Consequences

- **正面**：幼体起点干净（无遗留数据语义需要兼容）；H-4 的向后兼容推断行可删除（无存量数据须兼容，R-10 分支 1）；"V0 代码 / 数据不默认 KEEP"（规则 12）落地；用户将来的迁移决定有清晰入口（独立迁移任务 + 一次性迁移工具，不进 Core）。
- **代价 / 限制**：V0 既有经历 / 记忆 / 能力不自动进入 V1——用户将来若决定迁移，须接受一次性映射任务的成本（V0 schema → V1 Ontology）；V0 数据文件本身原地保留，其归档 / 删除是另行用户决策（U-2：未读，唯一演化历史残留，规则 7 精神，不得直接 rm）。
- **显式保留**：迁移最终状态 = UNKNOWN（用户决策）；V0 数据归档 / 删除 = UNKNOWN（U-2）。
